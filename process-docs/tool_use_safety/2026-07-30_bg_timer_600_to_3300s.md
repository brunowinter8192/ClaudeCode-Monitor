# Canonical Background Timer: 600s → 3300s

## Context (2026-07-30)

A prior worker session hit its context limit mid-edit on the canonical background-sleep-timer
rename (10min → 55min). Its changes sat uncommitted in a dead worktree, never reviewed or
verified: `_TARGET` in `rewrite_background_sleep.py` bumped `"sleep 600 && echo done"` →
`"sleep 3300 && echo done"`, plus matching test-expectation and DOCS.md edits in 5 files. This
session carried the same edits over by hand (read-and-reapply, not `git merge`, per worker
isolation rules), reviewed them, and closed the verification gaps the dead worker never reached.

## What Was Verified

**Real subprocess drive** of `rewrite_background_sleep.py` (stdin JSON → actual stdout, not an
import-and-call):

| input | run_in_background | result |
|---|---|---|
| `sleep 600 && echo done` | true | rewrite → `sleep 3300 && echo done` |
| `sleep 3300 && echo done` | true | no-op (already canonical) |
| `sleep 42` | true | rewrite → `sleep 3300 && echo done` |
| `sleep 600 && echo done` | false | no-op (foreground) |
| `sleep 5 && ./run.sh` | true | no-op (not sleep-only) |

All 5 matched expectation. Existing smoke suites also re-ran clean: `test_rewrite_background_sleep.py`
(11/11) and `test_block_unauthorized_background.py` (9/9).

**Menubar scanner reachability.** The rename is pointless if `bg_timer.py::_scan_bg_sleep_timers`
(what auto-abort acts on) can't see a 3300s timer — a timer it can't see can never be aborted.
Started a real `(sleep 3300 && echo done) &`, called the scanner directly: the new PID appeared
in the returned `sleep_pids` set. The machine also had a genuine, pre-existing orchestrator timer
running (`sleep 600`, shorter remaining) — the aggregate `min_remaining` returned reflected THAT
timer, not the new one, because the scan buckets by resolved project and both fell into the
`'unknown'` bucket in this ad-hoc probe (no `cwd_to_project` mapping supplied). The new timer's
own individual remaining, computed from its measured 2s elapsed via the module's own
`_parse_etime`/remaining formula, comes to ~3298s — confirms detection, not just membership.
Test process killed and confirmed gone afterward; the real orchestrator timer was left untouched.

**Duration-agnosticism of the match surface.** Both `_SLEEP_ONLY_BG` (rewrite hook) and
`_CANONICAL` (`block_unauthorized_background.py`) match the sleep duration via `\d+` — the
canonical VALUE (3300) only appears in the exact-string equality check (`command.strip() ==
_TARGET`) used to detect "already normalized", never in the match regex itself. `bg_timer.py`'s
own scanner likewise matches `sleep <any digits>` generically. No other duration-dependent
matching surface was found across the two hooks or the scanner.

## Outcome

600→3300s rename is drop-in: no other code path hardcodes the old or new duration value outside
the `_TARGET`/`_CANONICAL` equality checks that were always meant to track it.
