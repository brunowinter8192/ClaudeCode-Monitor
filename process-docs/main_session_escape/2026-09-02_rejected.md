# Main-Session Escape on Background Task — Rejected (2026-09-02)

## The idea

Mirror the worker mechanism from `process-docs/escape_idle_worker/` in the main session: when
a command in the orchestrator's own session gets backgrounded, fire one Escape into its Ghostty
terminal, once per background-task id, so the orchestrator goes idle instead of polling its own
background process.

## Why it is dropped

The user decided against it on 2026-09-02. The orchestrator's only sanctioned background
command is `worker-cli wait`, and since the 2026-08-17 pull architecture (`process-docs/
timer-loop/`) its exit is the wake-up; the orchestrator goes idle by rule after arming it, and
the 2026-09-02 transition gate (same area) means an early exit no longer happens. There is no
polling loop left for an Escape to break, so an injected keystroke into the main session would
only add a new failure surface (wrong pane, Escape landing mid-prompt) without a remaining
problem to solve.

The worker-side Escape stays as it is; the two sessions have different shapes, because a worker
cannot be told by rule to go idle after every background launch, while the orchestrator can.

No code was written for this area; `dev/main_session_escape/` does not exist.
